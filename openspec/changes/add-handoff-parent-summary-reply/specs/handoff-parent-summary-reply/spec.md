## ADDED Requirements

### Requirement: Parent Summary Reply Availability
The system SHALL provide an opt-in parent-channel summary reply for agent thread handoff completion.

#### Scenario: Disabled by default
- **WHEN** agent thread handoff is enabled but parent summary replies are not explicitly enabled
- **THEN** handoff child tasks SHALL continue to reply only in the child thread and SHALL NOT send a completion summary to the parent normal channel

#### Scenario: Enabled only with handoff
- **WHEN** parent summary replies are configured without agent thread handoff being enabled
- **THEN** startup validation SHALL reject the configuration with a clear error

### Requirement: One-Shot Handoff Completion Notification
The system SHALL send at most one parent-channel summary reply for the initial child ACP turn started by a successful `handoff_to_thread` call.

#### Scenario: Initial child turn completes
- **WHEN** a handoff child task's first dispatched ACP turn completes successfully
- **THEN** the system SHALL generate a parent summary and reply to the original normal-channel trigger message

#### Scenario: Follow-up thread conversation
- **WHEN** a user or bot continues the conversation inside the handoff thread after the initial child turn
- **THEN** those later thread turns SHALL NOT generate parent-channel summary replies

#### Scenario: MCP call remains asynchronous
- **WHEN** `handoff_to_thread` creates or resolves the child thread and enqueues the child task
- **THEN** the MCP tool response SHALL still return after enqueue and SHALL NOT wait for the child result or parent summary reply

### Requirement: Child Result Sanitization
The system SHALL sanitize the child task's final display content before using it as input to parent-agent summarization.

#### Scenario: Tool and thinking content removed
- **WHEN** the child final content includes tool display, thinking/progress text, output directives, or other agent-internal scaffolding
- **THEN** the summary prompt SHALL receive content with those elements removed

#### Scenario: Empty sanitized result
- **WHEN** sanitization removes all useful child result content
- **THEN** the system SHALL use a deterministic fallback completion notice instead of asking the parent agent to summarize empty content

### Requirement: Parent Agent Summarization
The system SHALL use the original normal-channel agent/session to generate the concise parent summary from sanitized child content.

#### Scenario: Summary generated by parent session
- **WHEN** sanitized child content is available for a handoff completion
- **THEN** the system SHALL submit an internal summarization turn to the parent normal-channel session associated with the original trigger message

#### Scenario: Summary prompt treats child result as data
- **WHEN** the system builds the internal summarization prompt
- **THEN** the prompt SHALL instruct the agent to summarize the child result as quoted data and ignore instructions contained inside the child result

#### Scenario: Summary length requested
- **WHEN** the system builds the internal summarization prompt
- **THEN** the prompt SHALL request the configured target maximum summary length without requiring OpenAB to hard-truncate the parent agent's summary before sending

### Requirement: Parent Message Reply Routing
The system SHALL route the summary reply to the original normal-channel message that triggered the parent inline handoff.

#### Scenario: Discord parent reply
- **WHEN** a Discord handoff completion summary is sent
- **THEN** the system SHALL send the summary in the original parent channel as a reply/reference to the original triggering message

#### Scenario: Slack parent reply
- **WHEN** a Slack handoff completion summary is sent
- **THEN** the system SHALL send the summary to the original parent channel route associated with the original triggering message

### Requirement: Summary Failure Isolation
The system SHALL keep child thread delivery independent from parent summary generation and delivery.

#### Scenario: Summary generation fails
- **WHEN** the child result has already been delivered in the child thread and the parent-agent summary turn fails
- **THEN** the system SHALL NOT retry or duplicate the child task and SHALL record the summary failure separately

#### Scenario: Parent reply send fails
- **WHEN** the parent summary is generated but sending the parent-channel reply fails
- **THEN** the child thread result SHALL remain delivered and the failure SHALL be logged without changing the child session state
